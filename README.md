# 小圣杯增强组件 · 合并版

Bangumi「小圣杯」的增强组件。**一套脚本同时支持新旧两版页面** —— 脚本启动时自动判断站点版本，只激活匹配的那一套实现，所以只有一个组件、只需要启用一次。

| | |
| --- | --- |
| 组件页 | <https://bgm.tv/dev/app/7532> |
| 当前版本 | `build 20261125c` |
| 文件 | `小圣杯增强组件-合并版.txt`（单文件 · 无外部依赖 · 样式已内嵌） |
| 覆盖 | 圣殿列表 · 持股筛选 · 星光碎片 · 角色页 · 英灵殿 · 底栏开关 |
| 设置 | 全部存 `localStorage`，新版 / 旧版页面共用同一套键 |

---

## 安装

组件已发布在 Bangumi 组件库，**直接启用即可**：

1. 打开 <https://bgm.tv/dev/app/7532>；
2. 点页面上的「启用」；
3. 刷新任意小圣杯页面。

不需要安装脚本管理器，也不需要粘贴脚本。

看到右下角出现「圣殿」标签（新版竖排标签 / 旧版圆形按钮）就是启动成功。控制台会打印 `[圣殿工具条] 已启动（… build 20261125c）`，旧版页面打印 `[圣殿工具条·旧版] …`。

> 组件不依赖站点或原组件的任何全局函数，全部功能靠「DOM 监听 + 自有接口请求」实现，所以脚本被平台隔离在独立作用域里也照常工作。

## 三个主开关

圣殿控制台 →「按钮显示」最上面三行（新版、旧版**都有**，共用同一套键）：

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 圣殿总开关 | **开** | 管所有圣殿页相关功能。关掉后圣殿页整条工具条一律收起（各功能状态照常记忆），打开即恢复；只有它开着，下面的子开关区才展开可点 |
| 持股筛选（人物页） | **关** | 开启后人物页签才会出现「等级筛选 / 持股排序」两颗按钮、才接管人物列表；关着时**不发任何持股请求**，人物页保持站点原样 |
| 角色页面 | **开** | 关掉 = 隐藏角色页顶部的「等级信息 / 贡献情况」按钮栏与内联按钮 |

三个主开关分别记在 `tgs_temple_master_v1`、`tgs_hold_on_v1` 与隐藏表 `tg_temple_hide_v1` 里，改完立即生效，不需要刷新页面。

子开关区则是逐个隐藏工具条上的每个按钮 —— 只藏按钮，各功能状态照常记忆，重新打开即恢复。

## 详细说明

### 受损排序 / 退市筛选

- 受损排序：分批（500 座 / 次）把**全部**圣殿拉下来，几千座也覆盖，不受每页 24 座限制；算完后把「固定资产 < 上限」的按受损度从高到低排最前，其余保持原序，再按页交回原组件渲染（不会把几千张卡塞进页面）。可勾「只看受损」。
- 退市筛选：以乐园 <https://bgm.tv/rakuen> 的「ST 角色」为准（`chara/delist/chara`，即真正的 st1 / st2 / st3）。**圣殿等级 0 只是掉级，不算退市**。开启后扫描全部圣殿 + 退市名单 + 我的持股，只留正在退市的塔；扫完发现没有退市塔会自动关闭筛选并恢复列表。
- 两者首次开启都要全量扫描，几千座时有几十秒加载过程（面板上有进度），扫完结果会缓存。

### 一键补塔 / 一键献祭

- 一键补塔：未选等级会提示先等级筛选。选好后找出该等级下所有受损塔，按受损度排，勾选要消耗的星光碎片（不填数量 = 全部可用），依次调用 `magic/stardust` 并汇报结果，完成后自动刷新。有精炼 ≥10 的塔时可勾「不补精炼+10及以上的圣殿」。
- 一键献祭：把持股的「献祭值」推到目标线（建塔 500 / 二级塔 2500 / 自定义），每行可覆盖数量，留空即全额。献祭值 < 500 时系统要求单次 ≥100 股，面板会标 `*` / 「全献」提示。

### 人物页持股筛选（/user/{名} 的「人物」tab）

需先打开「持股筛选（人物页）」主开关（默认关）。

- **工具条**：人物页签只留「等级筛选 / 持股排序」两颗按钮，其余自动隐藏，与圣殿的等级筛选完全独立。
- **等级筛选**：人数取持股接口全量（不是当前页 48 个）；下拉底部另有「退市（ST）档位」ST1 / ST2 / ST3。
- **持股排序**：只有两档（多→少 ⇄ 少→多）；想回站点原顺序 → 下拉底部「关闭持股排序 · 恢复原顺序」。
- **接管方式**：站点那张列表整体隐藏，同一位置换上一个 class 与网格样式完全相同的容器，里面铺满按筛选与排序排好的卡片（克隆站点卡片，头像 / 名字 / 持股数 / 等级徽章按接口回填）。所以对全部人物生效、顺序真的变了，而不是在上方另贴一份清单。之所以另起容器，是因为站点是 React 渲染的，往它的列表里插节点一重渲染就被抹掉。
- **站点原列表必须持续藏住**：React 重渲染时会直接重写列表的 `inline style`，把 `display:none` 覆盖掉（只有 style 变化、没有 childList 变化，挂在 childList 上的观察器收不到）。组件改用 **class + `!important`** 的样式表规则（`.tgs-sitehid{display:none!important}`），再配一个「站点列表可见性看门狗」（`attributeFilter:['style']` 观察器 + 900ms 兜底轮询），发现被藏过的节点又亮起来就逐个硬按回去，并顺带把「容器张数不对」重推一次接管。
- **稳定性细节**：页签切换即使只改 `display` 也会被 400ms 的语义轮询发现；自己写 DOM 时开短静音窗口（`__tgsQuietUntil`）免得自己的观察器插进来还原列表；渲染完 400ms 自检容器是否在 / 是否可见 / 张数对不对，不对就重建；卡片结构认不出来（站点改版）时自动退回「只筛当前页」，不会把页面弄坏。

### 英灵殿

用户主页加「英灵殿」按钮，打开后列出英灵殿全部股票。数据来源：`chara/user/chara/tinygrail/{page}/500`（全量）、`chara/auction/list`（竞拍人数 / 数量）、`chara/user/chara/{name}/...`（我的持股）、`chara/user/temple/{name}/...`（我的圣殿，`Sacrifices ≥ 500` 视为已建塔）。

收藏夹按账号记在 `localStorage`（键 `tgs_vh_fav_v1_{用户名}`），换账号互不影响、刷新后仍在。收藏的股已经不在英灵殿时（退市 / 拍完下架），列表会明确写出「收藏的 N 只股现在英灵殿里已经没有股了」并逐条列出，同时说明**收藏仍然保留**。

### 星光碎片

新版接管 `#tg-character-search` 弹窗；旧版接管 `[星光碎片]` 后的 `#searchDialog`，并用 CSS 压制原版搜索框 / 列表 / 分页条（含原版异步 `.show()` 的反扑）。默认批量模式（点卡片即勾选同等级），每项可直接改充能数量，底部实时预览容量，执行前有明细确认窗。

## 注意

- **一键补塔、降塔、一键献祭、英灵殿出价都是真实操作**，会消耗固资 / 资金或改动站点数据，点之前看清楚。
- 筛选、排序、布局类功能只改你本地看到的画面，**不影响他人显示**。
- 退市名单一周才换一次，拉到一次就一直用；点「↻ 刷新」会清掉重新拉。
- 持股数据（`chara/user/chara` 全量）现在同一账号「在飞合并 + 8 秒内复用」：星光碎片扫描 / 一键补塔 / 一键献祭 / 持股等级四个地方共用一份，献祭或补塔完成、点「↻ 刷新」会主动失效。接口失败时进入 60 秒冷却，不会反复重发。
- 所有接口请求汇入一个全局限速器：在途 ≤6、相邻发起间隔 ≥80ms，遇到 429 / 5xx 按 1.5 倍退避，连续失败还会临时把并发降到 4。
- 如果整份脚本加载失败（控制台报 `Unexpected identifier` 之类），先确认没有别的「云同步 / 工具箱」在中间转存脚本文本 —— 它拿到截断内容再 eval 会让整份脚本语法错误。

## 排查

控制台可调两个诊断接口：

- `__tgsHoldDiag()` —— 持股列表 / 站点列表隐藏状态 / 看门狗 / 容器张数
- `__tgsDiag()` —— 页面结构识别结果

报问题时附上这两份输出，定位会快很多。

## 文件

- `小圣杯增强组件-合并版.txt` —— 组件本体（带完整说明注释），即组件页 <https://bgm.tv/dev/app/7532> 里发布的那份脚本
